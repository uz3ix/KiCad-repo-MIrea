## Что прикрепить

- `main.c` — программа AT89S51 с комментариями;
- `checksum.h` — функция суммирования;
- `rom_reference.h` — параметры варианта и эталонная сумма;
- `rom27c128.bin` — учебное содержимое внешнего ПЗУ (16384 байта);
- `prepare_rom.py` — создание образа и расчёт эталона;
- этот файл — описание алгоритма и порядка использования.

## Параметры варианта

| Параметр | Значение |
|---|---|
| Микроконтроллер | AT89S51, внутренняя Flash 4 Кбайт |
| Внешнее ПЗУ | 27C128, 16 Кбайт |
| Начальный адрес | 1000h |
| Длина области | 350 байт = 015Eh |
| Последний адрес включительно | 115Dh |
| Индикация ошибки | D1; P1.0 = 0 включает LED |
| Метод | Сумма байтов по модулю 65536 |

## Почему используется CODE

OE микросхемы ПЗУ подключён к PSEN микроконтроллера. Поэтому указатель объявлен с типом памяти `code` для Keil C51 или `__code` для SDCC. Компилятор использует инструкции **MOVC**. Чтение через `xdata`/MOVX формирует другой сигнал RD и не соответствует этой схеме.

EA подключён к +5 В: программа и константа эталонной суммы должны полностью находиться во внутренней Flash **0000h–0FFFh**. Адреса 1000h–115Dh читаются из внешнего ПЗУ. U2 удерживает младший адрес по ALE; U4 выбирает ПЗУ при A15=A14=0.

## Алгоритм программы

1. Выключить D1, обнулить признаки завершения и результата.
2. Записать FFh в P0 и P2 для работы альтернативных функций шин; разрешить вывод ALE.
3. Прочитать 350 байт с адресов 1000h–115Dh.
4. Сложить значения по модулю 65536.
5. Сравнить результат с `expected_sum`, размещённой во внутренней памяти программ.
6. При несовпадении установить P1.0 = 0 и включить D1; при совпадении оставить его выключенным.
7. Сохранить результат в переменных и перейти в бесконечный цикл. Кнопка SW1 сбрасывает МК и запускает проверку заново.

Для отладчика: `observed_sum` — вычисленная сумма, `test_finished` — проверка завершена, `test_passed` — сумма совпала. Выключенный LED до завершения проверки сам по себе не доказывает успех.

## Содержимое ПЗУ и эталон

В задании нет конкретного дампа или готовой эталонной константы. Поэтому приложен **демонстрационный образ**, выбранный для воспроизводимого примера:

- в области 1000h–115Dh записана последовательность `00, 01, ..., FF, 00, ..., 5D`;
- остальные байты образа равны FFh;
- эталонная сумма этой области: **9093h (37011)**.

Это вычисленный эталон выбранного образа, а не измеренный результат проверки устройства. BIN предназначен для внешней 27C128 и не является прошивкой микроконтроллера. Для физической проверки ПЗУ заранее программируется отдельным программатором; текущая схема предназначена для чтения.

Создать тот же образ заново (Python 3, запуск в папке code):

```powershell
python prepare_rom.py
```

Для другого **заведомо исправного** полного образа 16 Кбайт:

```powershell
python prepare_rom.py --input "C:\путь\исправный_образ.bin"
```

Скрипт обновит `rom27c128.bin` и `rom_reference.h` в своей папке. После изменения эталона нужно пересобрать программу МК. Не вычисляйте новый эталон по заведомо повреждённой памяти: это сделает сравнение бессмысленным.

## Сборка для SDCC

Из папки code с установленным SDCC для mcs51:

```powershell
sdcc -mmcs51 --model-small --code-loc 0x0000 --code-size 0x1000 --iram-size 128 main.c
cmd /c "packihx main.ihx > main.hex"
```

Ограничение `--code-size 0x1000` требуется, чтобы программа и константы не попали в область внешнего ПЗУ. По карте линкера убедитесь, что все байты кода лежат ниже 1000h. `main.hex` программируется во внутреннюю Flash AT89S51; `rom27c128.bin` — отдельно во внешнее ПЗУ.

## Сборка для Keil C51

Создать проект для AT89S51, добавить `main.c` и стандартный startup. Разместить код и константы только в диапазоне 0000h–0FFFh (BL51 CODE range `0x0000–0x0FFF`). Выбрать частоту 12 МГц. Заголовки `checksum.h` и `rom_reference.h` положить рядом с main.c. Проверить карту памяти и создать HEX. В C51 автоматически выбирается ветка с `REG51.H` и типом памяти `code`.

## Проверка и ограничения

По схеме проверены PSEN, CS_N и P1.0. На компьютере скомпилирована и выполнена общая функция `checksum_add` из исходников: проверен эталон, изменение первого и последнего байтов области, исключение соседних адресов и переполнение 16-разрядной суммы. Размер образа и границы диапазона проверены отдельно. Эти тесты не исполняли инструкции 8051 и не моделировали память.

Полная программа для 8051 не компилировалась: SDCC/Keil C51 в среде не установлены. На микроконтроллере и в симуляторе программа не запускалась; осциллограммы не получены. Аддитивная сумма может не обнаружить взаимно компенсирующие изменения нескольких байтов; это учебная проверка, не полный тест исправности памяти.
